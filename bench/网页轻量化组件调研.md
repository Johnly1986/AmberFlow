# 网页轻量化组件调研报告（面向 LayaWebUse 页面抽取层）

> 时间：2026-09-30 · 环境：Linux/CPU，LayaWebUse bench 测试台（4 fixture + quotes.toscrape.com 实站）
> 问题：浏览器 Agent 每一步都要把"当前页面"压进 laya 的 512–1024 token 窗口。
> 调研对象 = **页面状态轻量化组件**：可交互元素识别、DOM/AX 树裁剪、正文压缩三类。
> 所有数字为本机实测或一手源码阅读所得，出处链接在文末。

---

## 一、结论先行

1. **行业已收敛出三条技术路线**：CDP 增强 DOM 管线（browser-use）、ARIA 快照（Playwright `_snapshotForAI`/`aria_snapshot`）、LLM 语义 observe（Stagehand）。三者不互斥，最优解是分层混用。
2. **对 LayaWebUse 的直接可用增量**：`Locator.aria_snapshot()` 零依赖、单行调用，实测把喂给模型的状态文本压到现有方案的 **1/4 ~ 1/5**（quotes 首页 4266→995 chars；登录页 121t→23t），且自带角色归一化（textbox/link/button/combobox）。
3. **但 aria 快照不能替换执行句柄表**：它丢 `data-test`、`input[type]`、href 之外的属性——我们的 `_nav_rule/_affordance_rule/target_hint/_locator_for` 全建立在这些属性上。正确姿势是 **双轨制**：aria 裁剪视图 → 给 laya 当 state/criteria；现有 dict → 给执行器当 handle。
4. browser-use 管线里最值得抄的不是库本身（重依赖 CDP 全家桶），而是三个**算法点**：JS 事件监听器探测（CDP `DOMDebugger.getEventListeners`，无 DOM mutation）、paint-order 遮挡剔除（纯 Python RectUnion）、compound control 展开（select/date 的子部件）。

## 二、候选组件清单与实测

### A. Playwright ARIA Snapshot（内置，零新依赖）★推荐立即采用

- API：`locator.aria_snapshot()`（v1.49+，本机 playwright 1.58/1.63 均可用），YAML 风格缩进树，节点=`role "name"` + `[url=...]` 等少量属性。
- 上游定位就是 AI 场景：微软 2025-07 起专门优化（[PR #42034](https://github.com/microsoft/playwright/pull/42034) 修复 icon-only 可点元素被裁掉的问题；OpenClaw 等 agent 框架直接把它当唯一观测源，见 [issue #68059](https://github.com/openclaw/openclaw/issues/68059)）。
- **实测（bench fixtures + 实站）**：

| 页面 | 现行 extract_elements | aria 全量 | aria 裁剪(仅交互行) |
|---|---|---|---|
| testpages/product.html | 6 el / 109 tok | 13 ln / 62 tok | 6 ln / **25 tok** |
| quotes.toscrape.com/login | 7 el / 121 tok | 20 ln / 65 tok | 7 ln / **23 tok** |
| quotes.toscrape.com/（长列表页） | **30 el 触顶截断** | 141 ln / 4266 ch | 55 ln / **995 ch** |

- 附带红利：长页面不再被 MAX_ELEMENTS=30 截掉尾部（现行 cap 在 quotes 首页已触顶）；`textbox "Username Password"` 这类 label 污染在 aria 侧也给了我们 wrapper-label 提取同款教训。
- 局限（实测确认）：无 data-test/id/name/type 属性 → 规则层和 target_hint 无法在其上运行；纯 CSS 生成的 UI（伪元素按钮）不可见。

### B. browser-use DOMService（0.13.10，读源码拆解）

管线（`dom/service.py` 1245 行 + `dom/serializer/*` 约 2250 行，[DeepWiki 总览](https://deepwiki.com/browser-use/browser-use/5-tools-and-action-system)）：

1. **采集**：DOMSnapshot.captureSnapshot + DOM.getDocument + `Accessibility.getFullAXTree` 三路合并成 EnhancedDOMTreeNode（[enhanced_snapshot.py](https://github.com/browser-use/browser-use/blob/main/browser_use/dom/enhanced_snapshot.py)）。
2. **交互性判定**（`clickable_elements.py`，多级信号级联）：
   - CDP JS 监听器探测（`is_clickable_by_listeners`，无需 onclick 属性——这是多数静态选择器库漏掉的 SPA 场景）；
   - 交互 tag 集 `{button,input,select,textarea,a,details,summary,option,optgroup}`；
   - 交互属性集 `{onclick,onmousedown,onmouseup,onkeydown,onkeyup,tabindex}`；
   - computed style `cursor:pointer`（来自 snapshot，覆盖"div 假装按钮"）；
   - role/aria-* 与 `data-action` 兜底；SVG 仅在显式 handler 时算交互。
3. **裁剪**：viewport containment（阈值 0.99 默认可配）、paint-order 遮挡剔除（`RectUnionPure` 纯 Python 矩形并集，[paint_order.py](https://github.com/browser-use/browser-use/blob/main/browser_use/dom/serializer/paint_order.py)）、opacity/display 过滤但**保留 file input 与 shadow host** 两个特例。
4. **序列化**：`[index]<tag attrs>text/>` 扁平格式 + compound control 展开（select→options、日期框→分段部件），正文只留 leaf 文本；另有 markdown 通道（markdownify，`markdown_extractor.py`）。

对 LayaWebUse 的可移植件：**监听器探测**（我们 INTERACTIVE 选择器漏掉 addEventListener 绑定的 div 按钮）、**遮挡剔除**（解决"点到了看不见的元素"类 inert）、**file-input/shadow-host 保活特例**。整体库不建议引入——依赖 cdp_use + 自己的 browser session 栈，与 Playwright 路径重复。

### C. Stagehand observe/act/extract（Browserbase，v4.1.0 py）

- `observe(instruction)` 返回带 selector/description/method/arguments 的动作候选列表；`act` = observe+execute；`extract` 走 zod schema 的结构化抽取（[docs](https://docs.stagehand.dev/v2/basics/observe)）。
- 关键设计：**视觉(DOM diff screenshot)+HTML 双路喂 LLM**，官方明确给出降载开关——`waitForActionTimeoutMs`、缓存 act/observe 结果、用小模型跑 observe（[speed optimization](https://docs.stagehand.dev/v4/best-practices/speed-optimization)）。
- 与我们的分工哲学相反：Stagehand 让 LLM 每步都参与选择；LayaWebUse 是"LLM 编排一次固化、laya 每步执行"。**它的价值在我们的 planner 侧**（plan 阶段一次性 observe 出候选动作+selector，直接生成 target_hint），而不是 executor 侧。API 每次 observe ≈ 一次 LLM 往返的成本决定了它不能进步骤循环。

### D. Skyvern（vision-first，备选对照）

- 架构 = Vision（截图+LLM 看图）与 DOM（CodegenLLM 生成 Playwright 代码）双引擎竞速/降级（[docs](https://www.skyvern.com/docs/developers/getting-started/introduction)）。
- 对自托管 CPU 场景不合适（每步大模型视觉推理），记录为反例：**页面轻量的另一极是"干脆不要 DOM"**，适合无 a11y 标注的重样式站点。

### E. 学术侧标定（为什么必须裁剪）

- Mind2Web 实测：**页面平均 268.4 个可交互元素**，其方案是 ModernBERT-base 二分类器先滤"可能交互"再进 prompt（[OpenReview PDF](https://openreview.net/pdf?id=zQlEEfSYTQ)）。这解释了 browser-use 为什么要整套交互性级联、以及我们 k=8 shortlist 为什么必要。
- TinyFish 的观点文（[The Accessibility Tree Wasn't Built for AI Agents](https://current.tinyfish.ai/issue/33/foundations/article/22079/the-accessibility-tree-wasnt-built-for-ai-agents)）提醒：AX 树的 name 计算会折叠/丢失营销类页面的真实可见文案——aria 路线要配"可见文本兜底"，即我们的 main_text/state_text 通道仍需保留。

### F. 正文压缩小工具（state_text 的替代品）

- trafilatura / markdownify（browser-use 的 markdown 通道用的就是 markdownify）：适合"读页面内容"型子目标（价格核对、成功文案检测），quotes 首页 raw inner_text 1668ch；trafilatura 未装（pip 可补），markdownify 纯 Python 轻量。
- 现行 `state_text`（关键词重叠压缩，budget 320）在同页压到 253ch，效果同级且确定性——**保留**，trafilatura 作为"叙事型页面"的可选第二档。

## 三、落地建议（按 ROI 排序）

| # | 动作 | 成本 | 预期收益 |
|---|---|---|---|
| 1 | criteria 改由 **aria 裁剪行** 构建（双轨：aria 视图给 laya，属性 dict 给执行器，ref 对齐靠同一轮 extract_elements） | 半天 | 状态 token −75~80%；长页突破 30 元素上限；角色名天然进入指令语境 |
| 2 | 交互判定加 **CDP 监听器探测**（`page.evaluate` + `getEventListeners` 不可用时退 `DOMDebugger.getEventListeners` per-node） | 一天 | 找回 addEventListener 型 div 按钮（现 `[onclick]` 选择器的盲区） |
| 3 | 引入 **paint-order 遮挡剔除**（browser-use 的 RectUnion 思路，纯 Python <100 行） | 半天 | 消灭一类"inert 点击"，减少 forbidden 循环 |
| 4 | planner 侧试 **Stagehand-style observe**（或直接让 LLMPlanner 拿 aria 快照产 target_hint） | 半天 | hint 覆盖率自动化，向"全自动编排→固化→执行"闭环推进 |
| 5 | 不引入 browser-use/Skyvern 整库 | — | 避免依赖重复与 GPU 需求 |
