# 提名考卷为什么不可解：问题集合与答错原因分析

> 触发：项目方指出"**无条件约束下让决策模型选一个指令集，本身就是错误做法，无异于让决策模型猜指令**"。
> 本文用两份**逐行可复核**的冻结产物把这句话拆成读数：
> `bench/instruction-nomination-online/nomination-online.json`（线上 `decision-model-preview` 臂，2026-10-17）
> 与 `bench/instruction-nomination/nomination.json`（本地 laya 臂，S0 冻结账）。两份语料逐行对齐（已校验：165 行同 app#index）。
> 结论先说：**24.8% 不是模型能力读数，是这道题的可解度上限；97.6% 的错误来自"模型按文字作答、标签按实现判分"的错位。**
>
> **S0-v2 实测（2026-10-18，§6）证明根因是设计**：同一考卷、同一标签、同一问法，只把**页面上下文**补进题面——
> 决策模型 **24.8% → 63.6%**（超过 51.5% 基线），候选再按页面条件化后 **88.5%**（歧义组 **7.2% → 92.8%**）；
> 本地 laya 带同一份上下文也从 4.8% → 54.5%。

## 0. 结论先行

| 缺陷 | 读数 | 后果 |
|---|---|---|
| **题面欠定**（无页面状态） | 83/165 行 = **50.3%** 落在"同一句话、不同真值"的跨应用歧义组 | 答案由页面实现（`<select>`/按钮/滑块/日期输入）决定，题面里没有这个信息 ⇒ 不可解 |
| **语料选择偏倚**（闭集 5 项，真值只有 3 项） | 真值分布 click 85 / select 66 / fill 14；**list_pick 0、check 0** | 模型 80 次预测（list_pick 77 + check 3）**结构上不可能被判对**；而"最低价/排序"正是 list_pick 的语义域——恰好被语料排除 |
| **标签定义错位**（真值 = trace 首个 DOM 动作） | 40/165 行是多动作步；题面首动作族与真值吻合仅 74/165 = **44.8%** | fill 14 行中 13 行题面以"打开"开头；select 66 行中题面出现"下拉/选择"的**只有 1 行**——题面读不出真值 |
| **指令描述互相重叠** | click 的描述含"记录/提交"，list_pick 含"最低价/排序"，select 只说"下拉框" | 题面"记录…最低价"同时命中 click 与 list_pick 两条描述 ⇒ 按词面选任一条都"合理" |

**错误归因（124 行错）**：答 `list_pick` 77 行 + 答 `click` 44 行 + 答 `check` 3 行。
其中 **121/124 = 97.6% 是"模型跟着题面文字作答"**（77 行含"最低价/排序"词 → 答 list_pick；44 行题面首动词是"打开/点击" → 答 click），
标签却按"trace 里实际先执行了哪个 DOM 动作"判分。这不是模型猜错，是**题把对的判成错的**。

两个模型在同一题面上同病：线上 41/165（24.8%，0 弃权）、本地 laya 8/165（4.8%，**82% 塌缩到 list_pick**）——
都被"永远答 click"的零智能基线（85/165）碾压。**同一道题把两个不同模型都判成低于傻基线，就是题目失效的判据。**

## 1. 问题集合的解剖

### 1.1 题面：一句话，没有状态（合同外任务）

S0 臂问的是（`tools/instruction_nomination.ts` + `src/nominate.ts` 的单一出处）：

```
state:      { goal: <这一步的自然语言描述> }                 ← 只有一句话
questions:  act: { type: "choice", instructions: <固定措辞>,  ← "下一步该执行哪条指令"
                   criteria: { click: "点击一个链接、按钮或控件（打开/进入/提交/记录）",
                               fill:  "在一个文本输入框里填写文字（日期、名称、编号）",
                               select:"在一个下拉框里选择一个选项",
                               check: "勾选一个复选框或单选框",
                               list_pick: "从列表行里按数据规则选一行（最低价/最高价/最小/最大）" } }
```

决策模型（SystemOne）的合同是 **state（页面视图）+ criteria（候选）**——它被训练的是"在这个页面上，这些候选里哪个对"。
把 state 换成一句孤立的话，就是把决策模型当**句子分类器**用：它没有任何页面证据，只能按先验+词面猜。
问句里"next"也无从谈起——没有"当前页面/上一步"，"下一步"不存在。

### 1.2 语料选择偏倚：闭集 5 项里 2 项永远不可能正确

`collectCorpus` 只收 **kind=browser 且首动作 ∈ {clicked, filled}** 的步：

- `list` 步骤是 `kind: list`（组合指令 `list_pick` 的执行形态）——**被排除**，所以真值里没有 list_pick；
- 勾选/单选（`check`）在 trace 里记成 `clicked`——所以真值里没有 check。

实测真值分布：**click 85 / select 66 / fill 14，list_pick 0 / check 0**。
模型答 list_pick 77 次、check 3 次——**80 次预测在一次公平考试里不可能得分**。
而题面里恰恰有 77 行带"最低价/排序/记录最低价"字样（其真值是 click 41 / select 36）：
**语料把 list_pick 最该出现的步骤全部排除了，却把 list_pick 留在候选里。**

### 1.3 标签定义错位：trace 首个动作 ≠ 这一步在说什么

真值口径是 `truthOf()`：取 trace 里**第一个 clicked/filled 动作**。这对"一句话→一步"的步骤通常是单动作，
但本语料大量步骤是**多动作**（打开列表 → 填日期 → 筛时段），首动作只是流水线的第一个动作：

- 40/165 行题面含 ≥2 个动作族；线上臂在这 40 行只对 **4** 行，单动作行 122 行对 34 行；
- 题面首动作族与真值吻合 **74/165 = 44.8%**——把标签定义为"题面读得出的动作"时，**超过一半的题面读不出真值**；
- 典型：`打开 {date} 昆明到北京的航班列表，并把出发时段筛选为 {time}` 的真值是 **fill**（13 行）——
  执行器先填日期字段；模型答 click（题面首动词"打开"）→ 判错。

### 1.4 跨实现歧义：同一句话，四个应用四种真值（**决定性证据**）

把日期/时段/价格归一化后，**4 组、共 83/165 = 50.3%** 的行属于"同一句话、不同真值"：

| 归一化题面 | 行数 | 真值分布 | 说明 |
|---|---|---|---|
| `打开 {date}昆明到北京的航班列表，并把出发时段筛选为 {time}` | 35 | click 5 / **select 20** / **fill 10** | 同一句话：ctrip 点按钮、farehaven 用 `<select>`、flyquest/voyagio 先填日期 |
| `把 {date}的航班列表按价格从低到高排序` | 35 | click 5 / **select 30** | ctrip 点排序链接；farehaven 用下拉排序 |
| `把 北京 {date} 入住的酒店列表按价格从低到高排序` | 7 | select 6 / click 1 | 同上 |
| `打开 北京 {date} 入住的酒店列表，并把价格上限设为 {price}` | 6 | select 4 / click 1 / fill 1 | `<select>` / 按钮 / **滑块**（fill）三种实现 |

**同一句自然语言，正确答案取决于页面上的控件实现（下拉 / 按钮 / 滑块 / 输入框）**——
这正是决策模型需要 `state` 的原因；题面里没有页面，就没有任何模型（决策模型或别的分类器）能确定答案。
模型在这些行里"按句面"答 list_pick / click，被判错，但这**不是识别错误，是题目少给了条件**。

### 1.5 指令描述重叠：候选之间本身不可判别

`instructionCriteria()` 的 5 条描述里：click 的描述含"打开/进入/提交/**记录**"；list_pick 的描述含"**最低价**/最高价/排序"；
select 的描述是"在**一个下拉框**里选择一个选项"。于是：

- 题面"记录 …最低价的航班"同时命中 click（记录）与 list_pick（最低价）两条描述的词汇——选哪条都说得通；
- 题面"把…列表按价格从低到高排序"（35 行）只含 list 词，模型答 list_pick 是**按描述办事**；
- select 的 66 行里题面出现"下拉/选择"的**只有 1 行**（其余是"打开…筛选…""排序"）——题面里没有"下拉框"，
  模型无法从语言区分 select 与 click/list_pick。

## 2. 答错归因（把 24.8% 拆开）

### 2.1 混淆矩阵（线上臂，全 165 行）

| 真值 | n | 线上答 click | 线上答 list_pick | 线上答 check | 归因 |
|---|---|---|---|---|---|
| click | 85 | **41 ✓** | 41 | 3 | 41 行题面含"最低价/排序" ≠ 语料意图；3 行"筛选/勾选"措辞 |
| select | 66 | 30 | 36 | 0 | "排序"行归 list_pick（30+ 是 farehaven 下拉）；"打开…筛选"行归 click |
| fill | 14 | 14 | 0 | 0 | 13 行题面首动词是"打开"（填日期在句尾）；1 行"搜索 琥珀（结果没到位再搜一遍）" |
| **合计** | 165 | 85 | 77 | 3 | 正确 41 |

### 2.2 97.6% 的错误是"文字 vs 实现"的错位

124 行错误 = 77（答 list_pick，全部落在含 list 词的题面上）+ 44（答 click，全部落在题面首动词为"打开/点击"的行上）+ 3。
**没有一个错误形如"模型看懂了句子却理解错了指令"**——绝大多数是"模型照句子字面答，标签按 DOM 实现判"。

### 2.3 规则臂同样被这道题判低——说明是题的问题，不只是模型的问题

rules 臂 36/165（21.8%）：它按"最低价→list_pick、点击/记录→click"的关键词梯级作答，**35 次 list_pick 预测被判错**。
规则臂在**运行期**不是错——它是候选生成器，由该步信号裁决；但 S0 用"5 选 1 准确率"给它打分，
等于用"标签对不对"评判一个"候选是否可用"的组件。**S0 的指标口径本身对每个臂都不成立。**

### 2.4 真凭实据的"不接线"依据：边际，而不是被污染的准确率

- 在 rules **弃权**的 45 行上：线上 ③ 只对 **3** 行（first-candidate 对 9 行）——③ 在"规则没把握"处没有增量；
- 阶梯首猜（rules → ③ → ⑤首位 click）39/165，低于基线 85/165；
- 所以运行期不接 ③ 的**正确依据**是"③ 在边缘上没有净贡献"，而不是"24.8% < 51.5%"这个被标签污染的对比。
  （即便把标签全部修好，③ 在这题上也没有证明过自己的净收益。）

## 3. 这道题能证明什么、不能证明什么

**能证明**：
1. **"desc-only + 无条件 + 单标签闭集选择"不是决策模型能做的题**——它的合同要求 state；
2. 决策模型**不应被当成句子→指令分类器**；这条路（把语义解析外包给决策模型）应关闭；
3. 任何新模型进来都该先赢"零智能基线"——本题的基线（永远 click）能赢过两个模型，标明**题目本身无效**。

**不能证明**：
1. 不能证明"决策模型不能提名"——**受约束的提名题没测**（候选来自页面 affordance、带 state、标签来自步骤声明/多标签）；
2. 不能证明"决策模型不能用于生产"——元素拾取兜底（对照台 3/4、全量套件 16/17）是另一份考卷；
3. 不能证明"模型比规则弱"——规则在这份考卷上也是 21.8%，它只是同样被标签口径误伤。

**对既有文档表述的修正**（已同步改）：
- `docs/NL_FLOW_DESIGN.md` S0 一行的读法：从"model 臂 4.8% ≤ 基线 ⇒ ③ 不可行"改为
  "**该题形状不可行**（标签/语料/合同三层偏倚，见本文）；③ 在受约束题面下未测，运行期仍不接线（依据改为边际读数）"；
- `docs/ONLINE_MODEL_TEST_REVIEW.md` §1：24.8% 加注"题目有效性问题见本文"。

## 4. S0-v2 设计（若项目方要重做"提名"这件事）

正确姿势不是"换更强的模型"，而是**给题加条件、把标签修对**：

1. **标签条件化**：动作族由**页面 affordance** 唯一决定（页面有 `<select>`→select、有 `<input>`→fill、
   有复选→check、有列表行→list_pick、否则 click），或直接取步骤声明（语义流 `instr`/`list_step`）；
2. **语料补全**：纳入 `kind=list` 步骤与勾选真值——闭集 5 项都必须是可能正确的，否则先验分布就是假的；
3. **问法带 state**：`state = {goal, url, title, 页面视图（元素池/控件类型摘要）}`，
   `criteria = "指令 × 本页可用元素/值" 的具体候选`（如 `select[出发时段]`、`fill[出发日期]`），
   而不是 5 个抽象操作名——这才是决策模型的合同形状；
4. **多标签/意图族**：一步可以同时是"记录最低价"（意图）与 click（DOM 事实）——评分改集合命中，或分两问
   （"要做什么" vs "用什么控件做"）；
5. **指标换端到端**：阶梯首猜成本（枚举平均位置）+ 信号裁决成功率 + 完成率，而不是 5 选 1 准确率；
6. **两条通道分开测**：语义解析交给 **LLM 老师（④）**——本轮真跑已证明 qwen3.8-flash 老师可用
   （`rule 1 · laya 0 · escalate 3 written back 3 · blocked 0`）；决策模型只在"受约束选择"的题上测。

## 5. 复算与边界

```bash
# 线上臂产物（含逐行预测/混淆/延迟）与本地 laya 臂产物（S0 冻结）：
jq '.predictions, .scores, .confusion' bench/instruction-nomination-online/nomination-online.json
jq '.predictions["model"], .scores.model' bench/instruction-nomination/nomination.json
# 本文所有数字都可从这两份 JSON + rows[].desc/truth 复算；歧义组 = 归一化（日期/时段/价格→占位）后
# 同题面不同真值的组（4 组 83 行）。
```

**边界**：
- 单次运行、单服务版本；"同一题面不同真值"按日期/时段/价格归一化分组，跨站措辞完全一致的才算同组（本文只报了 4 组，未报长尾）；
- 归因中"模型按词面作答"是从预测与题面词面的一致性推断的（96.7% 的错误行满足该形态），不是读模型内部；
- 54 行的单动作、题面首动作族与真值一致的行里模型仍错——说明模型**并非完全无过**；但 80 次结构性死选项 +
  83 行跨实现歧义 + 44.8% 的题面可读率，已足以判定**这道题不能用来给"③"打分**；
- 本文只改文档与注释，不改运行期行为（③ 本来就不接线）；S0-v2 未实现，需要项目方批准后另行立项。

## 6. S0-v2 实测：把页面上下文补进题面（2026-10-18）

**设计**：与 S0 **同一语料（14 包 / 165 步）、同一真值、同一闭集、同一问法**，唯一变量 =
题面里有没有页面上下文。页面状态在**每步开始时**采（`captureStateView`：URL/标题/正文摘要 240 字/
控件能力摘要 `{text_inputs, selects, checkboxes, clickables, prices}`），随题面进 `state`。

| 臂 | 正确率 | 歧义组（83 行，同一句话跨应用不同真值） | 非歧义组（82 行） |
|---|---|---|---|
| first-candidate（永远 click，基线） | 85/165 = **51.5%** | 12/83 = 14.5% | 73/82 = 89.0% |
| rules（① 关键词梯级） | 36/165 = 21.8% | 6/83 = 7.2% | 30/82 = 36.6% |
| **nostate**（复现 S0 的"猜"臂：state 只有 goal） | 41/165 = **24.8%** | 6/83 = 7.2% | 35/82 = 42.7% |
| **context**（补页面状态） | **105/165 = 63.6%** | 32/83 = **38.6%** | 73/82 = 89.0% |
| **context-candidates**（上下文 + 候选描述带本页可用性） | **146/165 = 88.5%** | 77/83 = **92.8%** | 69/82 = 84.1% |
| laya-context（本地 laya 带同一份上下文） | 90/165 = 54.5% | 12/83 = 14.5% | 78/82 = 95.1% |

**读数**（只报告，不裁定）：

1. **页面上下文就是那个缺的条件**：nostate 24.8% → context 63.6%（+40pt），歧义组 7.2% → 38.6%（5.4×）——
   同一模型、同一题，只补了页面信息；**"模型不行"的解释被证伪，设计缺陷的解释被证实**。
2. **候选也要按页面条件化**：只给页面（context）能到 63.6%，把"本页有什么控件"写进候选描述后到 **88.5%**，
   歧义组 **92.8%**——因为跨实现歧义正是"这页用下拉还是按钮还是滑块实现"的问题，候选可用性直接给了答案。
   非歧义组 89.0% → 84.1% 略降（8 行波动，单次运行，不作结论）。
3. **本地 laya 同向改善**（4.8% → 54.5%，非歧义组 95.1%）：连一个 4.8% 的模型都能被上下文救到这个水平，
   进一步说明 S0 的低分主要来自题目而不是模型强度。
4. **代价**：每臂 165 次咨询；nostate 74.4s / context 78.2s / context-candidates 95.8s（均值 ≈450–580ms）。

**边界**（不吹过头）：

- 真值仍是 trace 首个 DOM 动作：上下文能消除"跨实现歧义"，**不能修复"多动作步只取第一动作"的标签错位**——
  那部分要改标签口径（§4 的 1/4 两条）。所以 88.5% 是**这份标签下的可达上限**，不是"指令提名已解决"。
- 页面状态是只读摘要（正文 240 字 + 控件分组），信息量是近似；完整 DOM/元素级候选会有不同数字。
- 单次运行、单服务版本；网络臂不进 CI；S0 冻结产物不动（本文与 `bench/instruction-nomination-context/` 是另一场考试）。

**对架构的含义**：S0 的旧结论"③ 不可行"**只对 desc-only 且无上下文的题形状成立**。正确构造下（页面状态 +
页面条件化候选）③ 在 165 条上 88.5%、在原本不可解的 83 行上 92.8%——**③ 从"死档"变成了"设计对了就可能接线"**。
但运行期接线是另一个问题（页面上何时问、问完由该步信号裁决、成本/延迟、与 ①②⑤ 的边际），**本轮未做**，
属显式下一项。

**产物与复算**：

```bash

export TOKEN_PLAN_ENDPOINT='https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/systemone'
```

## 7. 运行期接线落地（2026-10-18，用户裁定）

三个裁决：**① 允许 ③ 真正收窄元素池；② 纯运行期不回填指令记忆；③ 仅对 `nominate: true` 的步问。**

### 7.1 行为（`semantic-flow --nominate-provider NAME`，缺省不接 = 逐字节不变）

1. **触发面**：仅 `nominate: true` 且没有 `instr` 锁的步；且只在 ②学习映射、①规则都弃权时才问
   （梯级顺序不动；S0 语料上 ①弃权面 = 27.3%）。
2. **题面**：问之前按本步 URL 守卫导航到 start 页，抓**只读页面状态**（URL/标题/正文 240 字/控件能力摘要），
   连同**条件化候选**（"本页有下拉 N 个（出发时段）"）一起发给决策 provider——即 S0-v2 的 88.5% 构造。
   **抓不到上下文就不问**（没有页面的问法 = 让模型猜，S0 的教训）。
3. **提名族 = 软先验 + 有界修复**（2026-10-18 推敲后改版，取代最初的硬过滤）：
   模型提名是元素动作族（click/fill/select/check）时，候选池**按该族排序**（其他族元素**仍在候选与
   上下文里**——结构族 ≠ 语义动作：`div[role=combobox]` 是 click 族但语义 select、`contenteditable`
   是 click 族但语义 fill、`input[type=range]` 是 fill 族但语义设值；其他族元素也可能正是真目标）。
   只有当解析出的动作族与提名**不符**（或根本没解出目标）时，才做**一次有界修复**：用该族窄池重解析
   （规则优先、模型次之），仍不成立 ⇒ `nominated_family_empty`（本页无该族）或
   `nominated_family_mismatch`（有该族但不过闸）结构化停因——**绝不执行与提名矛盾的动作**。
   成本纪律：软先验零成本，修复只在走向停止时付一次。**只有 `via=model` 才启用**；规则/档案/枚举档不变。
4. **fail-closed**：provider 抛错/超时/池外答案 ⇒ 该档弃权，落⑤枚举，旅程不被打死。
5. **纯运行期**：不写指令记忆（不 staged、不重放门、不影响 ②）；账单只记本次的模型咨询。
6. **账**：`nominate_bill.model = {asks, abstains, errors}`、结果带 `nominate_provider` 身份、
   报告行 `· 提名 rule N · model M（…）`。
