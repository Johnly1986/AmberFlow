# 第二次按同一准绳的独立审查：这次审的是**架构**（2026-10-14）

> **准绳（项目方原话，与上一轮同一把尺）**：决策模型的引入，是为了**简化流程配置**、**增加弹性与容错**。
>
> 与上一轮（[DECISION_MODEL_PURPOSE_REVIEW.md](DECISION_MODEL_PURPOSE_REVIEW.md)）的分工：那轮审的是
> "模型"（它选得对不对、闸门配不配）；**这轮审的是"架构"**——距离上轮已过去 W0（换信号否证）、
> W1（风险头声明着省）、W3（漂移族）、provider 注册表（含 JevK5 与零智能基线）、D3/R-4（no_progress）
> 与开箱测试轮的全部改动。上轮的裁定是本文的**被审对象**，不是引用的权威。
>
> 独立性声明：本文每个数要么本轮重算、要么本轮新测；本轮新测的最重要一条是 **§B2 漂移族真模型臂
> （0/3）**——它把上轮"模型低于零智能基线"升级为"模型在**为它的弹性专门设计的验收台上**一格未兜"。

## 0. 一句话结论

**"简化配置"这个目的，架构已经达成——但达成它的是编译器/录制器（零模型）与 learned-hint 闭环
（模型唯一被测正的贡献，却没接进主链路）；"弹性与容错"这个目的，模型的实测贡献在稳态语料是 0、
在漂移台是 0/3、在 no-hint 对照里低于零智能基线——弹性真实由声明式三件套与梯级卫生承担，
它们是执行器的性质，不是模型的性质。** 架构没有把模型放错位置这么温和——它把模型放在了
**两个它赢不了的档位**上（运行期选择、风险投票），而它**唯一赢过的地方**（学到即规则的闭环）
被实现成了侧门。

## A. 审计面一：简化流程配置——谁真的把它简化了

### A1 主力是编译器三件套，全部零模型

`apps:matrix` 本轮实跑原话：*"由 spec/代码生成的 8 个、演示录制的 2 个（合计声明 2209 行不再由人抄写）；
手写 13 个——剩给'人'的只有 invariants / notes / 探针这些判断与测量"*。
`apps:gen --check` 8/8 不漂（进 smoke 门禁）、`learn` 的零模型重放门、`plan:flow` 的重放门控——
**"配置变少"这件事没有一步依赖决策模型**。上轮 §2.1 的账（机械行由生成器吃掉、人写判断约 37 条）
方向依旧成立。

### A2 模型对"简化配置"唯一被实测的贡献 = learned-hint 闭环——真实、但窄、且没接进主链路

三条独立证据（本轮全部在场复现）：

1. **plan:flow 端到端**（开箱测试轮实跑）：gate 行 `rule 1 · laya 3 (written back 3)`——模型现场选对的
   3 步过零模型重放门后**变成规则**；二跑 `rule:match` 命中已学 hint。这是"模型→配置"的实物。
2. **`npm run hint:measure`**（上轮，冻结在 CLAUDE.md）：同一矩阵二跑 forwards 53→44（**−17%**），
   且两腿通过数相同——省的是推理，不是正确性。
3. **语义流回填环**（红线 2 有牙）：`replays_ok` 从 1 起算、连续 2 次不成立报 `drift` 撤下——
   学到的东西**可以被没收**，这是它敢进配置的资格。

但它的边界必须同样写实：闭环**只摊销"模型已经选对"的步**（救不了它没做对的题）；CJK 页面上模型
选择正确率低（上轮 §2.3），所以学到的 hint 天然偏英文页；**且 app-runner——主执行链路——根本没接
hint-memory**（本轮 grep 证实：接线在 bench / plan-cli / semantic-flow 三处，都不在应用主路径上）。
已验收语料 201 步的账里没有任何一步是"上一轮跑学到的规则"。

### A3 新声明面对"简化"是净增——但用量证明它还没变成负担

`commands` 2 处、具名绑定 1 处、`next` 1 处、`policy` 0 处、`effect` 0 处（matrix 本轮实跑：
policy 列全 "—"）。上轮裁定（§3.7）"弹性正向、简化反向，要补编译侧入口"——**编译侧一年没补**
（B1 提议档卡在 LLM 端点，2026-10-13 裁定移出路线图）。低用量是双面的：没有"从意图编译"的入口，
这些面就停在"能力已备、需求未证"——不算债，但也不能算简化。

## B. 审计面二：弹性与容错——谁真的兜住了

### B1 稳态语料：梯级账单自己报 dead rung

本轮 `apps:suite` 页脚原话：*`梯级账单：规则/hint 决定 201 ｜ laya 决定 0 ｜ reobserve 决定 0 ｜
escalate 决定 0 ⇒ dead rung：laya、reobserve、escalate`*；`模型边际 0 ⇒ 退出码 4`（绿色不再替它背书）。
承担了全部已验收容错的是声明式三件套：`when` 7 / `retries` 11 / `next` 1（口径①，浏览器步）——
slowjet 的 5 次咨询 0 次过闸、救它的是 retries（README 已按实测改写成"反面教材"）。

### B2 本轮新测：漂移族的**真模型臂 = 0/3**（上轮缺的那条腿）

漂移族（W3）故意用 0.10 坏桩跑——它量的是"声明失效后规则还剩多少"（属性句柄 3/5、可见标签 4/5），
红格的职责归模型，但**没有任何臂测过真模型能不能兜**。本轮补测（工具 `tools/drift-real-arm.ts`，
真 ONNX 在位，同一执行器、同一夹具）：

| 红格（模型的责任田） | 桩臂 | **真模型臂** |
|---|---|---|
| ① 改 `data-test` × 属性句柄点名 | 红 | **红**（low confidence 0.04 < floor 0.25） |
| ⑤ 手机版 DOM × 属性句柄点名 | 红 | **红**（low confidence 0.04 < floor 0.25） |
| ④ 文案改写 × 标签点名 | 红 | **红**（low confidence 0.16 < floor 0.25） |

**模型在为"它的弹性"设计的验收台上一格未兜回。** 这把上轮的"删 hint 后 first-candidate 3/4 >
laya 0/4"（零智能赢）从"选择正确性"推进到"恢复正确性"：两个口径同向。
边界照写：3 个小夹具页；但上轮真机 ask-shapes（全池提问 3/14 对、6 次高置信错答会被采纳）
显示同一失败模式在真页面存在——**错的不是台子，是模型在这类题上的水位**。

### B3 弹性的真实来源是执行器性质，不是模型能力

把 no-hint 语料走完的是 `forbid（按签名）+ inert 判定 + retries + 完成信号裁决` 这套梯级卫生——
first-candidate 在同样夹具上 3/4 就是它的直接推论（provider 基线台的原话：*"基线不是可上线策略：
夹具里点错多为惰性，真实页面不是"*——这句边界也要反过来读：**真实页面上连零智能都走不完，
模型也没走得更远**（§2.5 真机数据）；真实页面的通关者至今是 authored 声明（live 8/8、长流程 34/34
全部 `rule:match`，本轮实测零模型出场）。

### B4 成本侧的好消息：保险现在声明着省

W1 落地（风险头 `rules-only` + `effect.irreversible` 跳过模型投票，实测 5.6–7.7×、结果逐字段相同）——
上轮"597 s 里大头是每步一次的风险头"这笔账有了便宜的持有法。但**没有任何包声明它**
（matrix policy 列全 "—"），默认仍是 `always`：省的是可选项，不是既得项。

## C. 架构级缺陷（本轮编号 R1–R6）

**R1｜弹性主张没有模型侧的验收臂。** 漂移族桩臂进 CI、真模型臂不存在——"模型兜漂移"永远不可能变绿，
也永远不会红。本轮 0/3 是这条臂的**首次测量**，结果红，且不在任何门禁里。
改：漂移族加可选真模型臂（`--real-model`，同 slowjet 两臂分目录的纪律），或文档明写"漂移的这几类
不承诺模型兜"。验收：臂进 `npm run verify` 可选档；0/3 或任何变化都有冻结产物。

**R2｜主链路没有学习环。** learned-hint 是模型对"简化配置"唯一被测正的贡献，却只活在 bench/plan-cli/
semantic 三处侧门；app-runner 的每次运行都从零开始问（如果它需要问）。
改：app-runner 接 `--learn-hints` sidecar（与 plan-cli 同一形状：**学到的永不进被审计的包**），
`apps:matrix` 加一列"上次运行学到/复用了多少条规则"。验收：同一应用二跑，第二跑的 `laya` 出场数
严格 ≤ 第一跑，且矩阵列非"未跑"。

**R3｜决策层可插拔了，但"一个智能横铺所有梯级"。** provider 注册表（laya-onnx/stub/基线/jevk5/自注册）
是上轮之后最重要的架构进步——它让"换智能"成为一等公民；但梯级四档（规则/模型/加宽/老师）共享同一个
provider，而两个目的需要不同智能：恢复档的实测最优是零智能遍历，作者档需要语言理解（laya 做不了，
裁定已写明）。改（观察，不急）：`policy` 声明面已有四键的先例，加"梯级 × 智能"维度前先等 R1/R2 的数。

**R4｜escalate 是**部署性**死档，账单却按**能力性**死档记。** 老师档需要 LLM 端点，本机未配置
（doctor 明说）——梯级账单报 "escalate 决定 0" 时，读者分不清"接了没用"与"根本没接"。
改：doctor 与套件页脚把 escalate 的状态打成部署态（`未配置（需 OPENAI_*）` vs `在场 0 挽回`）。
一行字的事，防的是"用没接线的档位证明档位没用"。

**R5｜A2′ 半落地状态要正式收口。** W0 杀掉的是 A1（换闸门信号）；A2′ 的两半（窄问扩大生效面 +
非破坏性步放开模型、事后由信号裁决）至今只有脚手架——`effect.irreversible` 已接**风险头**侧
（跳过投票），**放开选择**那一半没接。漂移族 3 红格因此没有任何机制能变绿，而文档里
"W4′ 剩下的两半都不依赖信分数"容易被读成"正在修"。要么立项要么按 §4 降级路线收口，
**不许挂着半截**。

**R6｜（正面确认，防审成批斗）架构的核心纪律全部经住了这次审计**：DOM 信号唯一真值、
零模型重放门、干跑取证、分层退出码、dead rung 自报、单一出处计量、双根发现、误输一行点名——
"弹性与容错"今天可审计、可没收、可复现，靠的全是这些**非模型**机制。问题只剩一个：
目的句里的主语。

## D. 裁定（对准绳两句的逐条回答）

| 主张 | 裁定 | 依据 |
|---|---|---|
| "决策模型简化流程配置" | **部分成立**：仅 learned-hint 闭环（−17% forwards、written back 有账），**且未接主链路**；配置简化的主力是零模型编译器 | A1/A2/R2 |
| "决策模型增加弹性" | **不支持**：稳态边际 0（exit 4 钉死）、漂移真模型臂 **0/3**（本轮新测）、no-hint 对照低于零智能基线 | B1/B2/B3 |
| "决策模型提供容错" | **收窄**：容错由 `when/retries/next` + 梯级卫生承担；模型票今天唯一改变的是"要不要问人"（W1 让它便宜） | B1/B3/B4 |
| "架构服务于该目的" | **达成，但经由架构提供的非模型机制**；模型的两处正确位置（学习环、作者期提议）一个未接线、一个卡端点 | C/R 全部 |

与上轮的关系：上轮的 6+3 档裁定**没有一条被本轮推翻**；被**加强**的是 §2.4/基线修正那条读法——
从"模型选择低于基线"到"模型恢复也低于要求且从未被验收"。被**更新**的只有一处：成本口径（§2.6）
因 W1 过时——保险变便宜了，"值不值"的天平动了一格，但没动方向。

## E. 建议顺序（性价比；每条带验收，不新造尺子）

> **落地状态（2026-10-14 续，项目方裁定 R1/R2 立项后）**：
