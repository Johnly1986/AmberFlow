# Laya 价值凸显优化方案

**日期**：2026-10-10 ｜ **状态**：提案
**判断前提**（本方案不是要让模型"多干活"，而是让它已有的活被看见——以下均有仓内实测背书）

## 一、诊断：价值为什么不可感知

| 现状 | 后果 |
|---|---|
| 离线夹具应用 100% 走 `rule:match, conf=1.00`，模型出场率≈0 | 用户（尤其插件用户）根本碰不到 Laya，"没权重也能跑"反而成了"模型没用"的证据 |
| 模型出场的场合（hint 落空、冷加载、reobserve 恢复）**没有汇总口径**——散在 step 日志里 | 一次 run 里模型救回几步、花了多少推理、缓存省了多少次，没有人报数 |
| 权重分发通道未建（1.7GB 产物，git 不含、npm 不拉、无下载命令） | 想体验模型兜底的人**无路可走**，价值再大也是零 |
| 叙事诚实但低调："规则先于模型"放在最前，模型只有一行"缺了走规则模式" | 品牌层面 Laya 是注脚，不是资产——而它名字都撑起了曾用名（LayaWebUse） |

**关键张力（必须守住的红线）**：实测 rules-on 8/8 vs rules-off 4/8——模型不是英雄，是保险。方案一切动作服务于"**把保险的价值量化可见**"，不搞"模型无所不能"的过度营销；`learn` 的零模型重放门控、DOM 信号唯一真值这两条产品灵魂不动。

## 二、北极星指标

把 Laya 从"看不见"变成"三组数"：

1. **出场率**：每次 run 报告 `model steps / total steps`（含 conf 分布）
2. **挽回率**：`laya:reobserve` 从 blocked 边缘救回几步（A/B 已钉：OFF 必 blocked、ON 完成）
3. **零成本率**：决策缓存命中（实测同一计划二跑 0 forwards、12→6）——"本地、免费、可审计"的定量表达

## 三、方案（P0→P3）

### P0 权重通道：让模型"装得上" —— 一切凸显的前提

- `npm run model:fetch -- --from <url>`：下载 `laya_dec.onnx` + `.onnx.data`，SHA256 校验，落到 `LAYA_ONNX_MODEL` 约定路径；私有源/镜像可配。
- `npm run doctor` 的模型项升级为**带操作的缺件报告**：现在只说"缺"，改成"缺 → 一条命令补"（对齐 Node/chromium 项的既有体例）。
- 桥侧：`amberflow_run` 的 summary 增加 `model: on|off(missing)` 一行，agent 转述时用户自然知道当前跑在哪个层级。
- **验收**：干净机器两条命令（`model:fetch` + `doctor`）后，live 用例的 step 日志出现 `laya:` 前缀。

### P1 出场量化：让每步判定"看得见"

- `apps:matrix` / `apps:suite` 每行加两列：**模型步数与 conf 摘要**、**reobserve 恢复数**（trace 已有 `how=laya:reobserve` 与方法级统计，纯汇总口径，无新机制）。
- run 报告（md）的"动作腿"表加"决策来源"小计：`rule 19 · laya 1 (conf 0.31) · laya:reobserve 1 · cache 命中 6/12 forwards`。
- `cache:measure` 并入 `apps:suite` 的标准输出（一次跑分同时给"模型参与"与"缓存节约"两个数）。
- **验收**：`transfer-slowjet`（实测唯一"模型决定成败"的离线包——冷加载问 laya 一次，靠它+retries 才 7/7）在 suite 输出里模型步数 ≥1，而 demo-app 为 0——**一张表同时讲出"规则消化了绝大多数"与"没有模型时 slowjet 会红"两种真话**。

### P2 叙事升格：README/ARCHITECTURE 给 Laya 一节"它在哪、值多少"

- README 加小节 **"为什么本地还养一个模型"**，四组可复现数字：
  1. reobserve A/B：60 个诱饵元素下，无模型加宽 = blocked，有 = 完成（`tests/reobserve.test.ts`）；
  2. slowjet：删掉模型那次提问 → 该子目标 0.16<0.25 直接 block（`--no-retries` 实测 0/7）；
  3. 缓存：同计划二跑 **12 forwards → 0，9.2s → 1.3s**（`npm run cache:measure`）；
  4. 诚实边界：CJK 页面上模型 0.03–0.09，**所以路由表按文字系统切、不按置信度切**（ECE 0.855 的教训写进故事——"我们比谁都清楚它不行在哪"，这是可信度而非减分）。
- 品牌句候选（README 首屏）："规则保证可复现，Laya 保证不轻言放弃，信号保证不作弊。"

### P3 场景扩台（谨慎、按数据决定）

- **风险裁决可视化**：危险步的拒绝/放行信息附上模型风险票（0.6 闸那票）来源，审计链更完整。
- **learn 的模型侧呈现**：录制若用到模型（非零 forwards），status 行从"0 model call(s)"扩展为"N model call(s), conf>floor on all"——门控仍是零模型重放，但**允许录制过程有模型参与并如实报数**。
- 暂不做：让模型写信号/不变量（"不可复现即拒存"的门正是拿掉模型才成立的，P3 前不动）。

## 四、工作量与顺序

| 阶段 | 体量 | 建议时点 |
|---|---|---|
| P0 通道 | 中（分发面：产物先要有个可拉的地方——若暂无公开源，先做 `--from <本地路径/file://>` 让通道成型，URL 源后补） | 立即 |
| P1 量化 | 小（全部数据已在 trace/result.json，纯汇总与两列展示） | 立即 |
| P2 叙事 | 小（文档 + 四组数字各附复现命令） | 随 P1 产物 |
| P3 扩台 | 中 | P0/P1 数据回来之后 |

**风险声明**：P1 上线后会出现"某应用模型步数=0"的行——这不是难看，这正是产品主张的证据（能规则化就别猜）；suite 的结论列建议同步加一句 `model not needed`，把"零出场"也讲成卖点。
