# 决策引擎分层设计 v5：引擎层拥状态机执行器与状态契约 × 应用层挂决策树（状态 + 转移表）× 实例挂参数

> 状态：**设计稿 v5**（2026-11-27）。四轮项目方纠正：
> **纠正一**：应用树 ≠ 站点知识，是应用层处理指令的**类型级行为逻辑**；
> **纠正二**：app.mjs 是应用实例，不代表应用层；
> **纠正三（结构本体）**：决策树 = 行为决策树——每个节点是一个决策单元，决策结果指向下一单元；
> **纠正四（语义澄清）**：例中的"弃权"只是**分支的示例形态**，不是普适契约——
> 结构更接近**有限状态机**：每个状态有自己的结果闭集，结果驱动转移。
> v3 的"五槽固定管线 + 否决树 IR"按纠正三推翻重写：**顺序与路由本身是应用数据**，不是引擎骨架。
> PM / 架构双代理研判的存活部分（§2 切割表、§5 验收、红线清单）沿用并重新归属。
> 锚点一律用符号名，不用行号。

## 0. 范式：项目方给定的执行步骤（本文的规范锚，逐字引用）

```
输入：用户输入
Agent：理解用户信息，分配调用决策引擎，注入提示词。
决策引擎：
    选择工具，是否有可用工具？有→下一步：弃权
    获取参数，是否有可用参数？有→下一步：弃权
    调用工具，调用是否成功？→下一个决策节点：弃权
    步骤是否符合预期？继续下一轮指令：重新选择工具：弃权
    决策步是否完成？完成通知：Agent 接管
Agent：查看结果，托底
```

提取三条不变量（语义 = **有限状态机**）：

1. **状态**：决策单元 = 状态。每个状态类有**自己的结果闭集**（引擎按 kind 定义、各不相同
   ——select-tool 四个、resolve-param 两个）；例中的"有→下一步 / 弃权"是**分支的示例形态**，
   不是"每个状态必须可弃权"的普适契约。
2. **转移**：结果驱动状态转移——`状态 × 结果 → 下一状态`，应用声明转移表
   （含纠正回环：verify-step 不达预期 → 退回 select-tool 重选）。
   终态两种：**完成通知**（正向叶）│ **交接**（落 12 停因闭集之一 → Agent 托底）。
3. **托底双向**：完成 → 通知 + Agent 查看结果；失败 → 交接 + Agent 托底。
   托底覆盖成功端与失败端。

三层结构（引擎层定义按纠正三细化为 walker + 单元契约）：

| 层 | 定义什么 | 现状落点 |
|---|---|---|
| **引擎层** | **状态机执行器**（逐状态求值、按结果走转移）+ **状态契约**（状态类型闭集、各类结果闭集）+ `gate()` 执行包裹 + 完成裁决调用点 + 预算 + 12 停因闭集 | `src/engine` |
| **应用层** | **决策单元树**：节点（单元实现）+ 边（结果路由，含纠正回环）+ 方言注册 | 声明腿先例：`AppAdapter`（自述"应用层的类型抽象"）；驾驶腿：`driveOnce` 的 if 链**待升格为显式单元图** |
| **应用实例层** | app.mjs：选应用类型、挂实例参数（goal / slots / 站点身份 / policy / 验收） | `$AMBERFLOW_HOME/apps/<id>/app.mjs` |

游戏引擎类比（项目方给定）：引擎定义行为树节点类型与黑板接口；每个角色类挂自己的树；
角色实例带参数上场。

## 1. 事实基线：这个范式在仓里已九成存在

**12 停因闭集 ≈ 交接终态的原因闭集**（不是巧合，是同一件事）：

| 范式单元 | 系统对应 | 交接终态停因（现有闭集成员） |
|---|---|---|
| 选择工具 | instruction-select（抽池 + 规则 + criteria 渲染 + 投票） | `low_confidence` / `target_ambiguous` / `no_model_runtime` |
| 获取参数 | param-select | `needs_value` |
| 调用工具 | act（`gate` 包裹） | `action_failed` / `unreachable` / `browser_dead` |
| 符合预期？ | step-verify | `stuck_inert`（连续不达预期且纠正无效——引擎已在计这个数） |
| 决策步完成？ | signal-check | `final_signal_held`（**正向叶** → 完成通知） |

**Agent 托底已闭集化**：4 兜底指令（resume 给值/点名、redirect 换道、finish 验信号、abort）
+ 交接块；交接块里的 `model_abstain{pool_size,asks}` 就是"选择工具单元弃权时的现场证据"。
**完成端复核已对齐**：`pilot_end` 摘要 + 产物恒带 `pilot:true`"不冒充 run 结论"。

**声明腿先例**：`AppAdapter`——一种应用类型 = 一个支持器，注册表纪律（拼错类型名加载期就红），
信号方言已分家（web = DOM 13 算子；cli/ssh/stdio = 进程观察信号）。

**实测缺陷做基线**（本会话轨迹）：`criteriaView` 只渲染 role+label+test+href+near →
池中搜索框有 `role:combobox / name:q` 而模型看到 `input ""` → 3 次决策 0 次有效推进。

**结论**：缺的不是能力，是两件事——把散在 `driveOnce` 里的 if 链**升格为显式状态机
（状态 + 转移表）**，并把"结果驱动转移"从引擎硬编码 if 分支**变成应用声明的数据**。

## 3. 决策树的语义 = 有限状态机（挂载协议，替代 v3 五槽）

**状态契约（引擎定义）**：

```
状态（决策单元）= { kind（闭集）, 判定(ctx) → 该 kind 的结果闭集 }   ← 各 kind 结果数不同
转移表 = 状态 × 结果 → 下一状态（应用声明；加载期校验每个已声明结果都有出边）
终态两种：invoke 叶（一次动作，经 gate）│ handoff 叶（一个交接，落 12 停因闭集）
黑板 = ctx（每状态求值的输入视图：goal / 池 / 账本 / 预算状态）
```

**状态类型闭集（首批，与范式五状态一一对应）**——注意每类结果闭集互不相同，
这就是状态机的**逐状态转移事件集**，不是统一的"满足 | 弃权"模板：

| kind | 引擎定义结果闭集 | 现有实现（建树材料全在仓） |
|---|---|---|
| select-tool | `picked{ref,conf}` \| `below-floor` \| `abstain` \| `no-model` | 抽池 + 规则 + `criteriaView` + `provider.pick` |
| resolve-param | `bound{value}` \| `needs-value` | slots/values 袋 + 两档匹配 |
| invoke | `changed` \| `no-change` \| `failed{code}` | affordance 族 + `actOnce`（`gate` 包裹） |
| verify-step | `as-expected` \| `retry{回环}` \| `inert{停因}` | 快照 diff + anti-repeat 计账 |
| check-done | `held` \| `not-held` | `checkSignal`（引擎裁决调用点 × 方言算子） |

**应用声明（浏览器默认树）**——把 `driveOnce` 的隐式 if 链升格为显式单元图：

```
[guard 引擎强制壳：信封 / expect_url / 预算]
   pass → [check-done]
[check-done]  held → ✅ 完成通知 → Agent 查看结果托底
               not  → [select-tool]
[select-tool]
   picked       → [resolve-param] → bound → [invoke]
   below-floor   → 恢复子图（宽扫→硬顶→升级→裁决）
                    挽回 → [invoke]｜仍低 → [rephrase?] → 重述 → 回注入面｜穷尽 → [handoff]
   abstain       → [handoff{low_confidence + model_abstain 现场证据}]   ← 应用可改路由：先重述再交接
   no-model      → [handoff{no_model_runtime}]
[invoke] → [verify-step]
[verify-step]  as-expected → [check-done]（步级判定）
                retry      → [select-tool]（★ 纠正回环：不达预期重选工具——固定管线缺的那条边）
                inert      → [handoff{stuck_inert}]
[check-done] not-held → 下一轮（回 guard，消耗 1 步预算）
```

**与"唯一执行循环"红线的关系**（更正 v3 的否决理由）：walker 是**决策面**的循环——
求值的是单元、走的是结果边；`invoke` 单元经 `gate()` 走既有唯一执行器。
**不存在第二个浏览器执行循环**。v3 把"树结构"与"执行循环"混为一谈，纠正三推翻该否决。

**加载期校验**（挂载 = 校验后装配，无运行时调度器）：每类已声明结果必须有出边；
边指向存在的单元；叶子必须是 invoke/handoff；guard 壳由引擎强制注入、应用不可移除；
方言算子未注册 → `config_error`。

**永不可挂载**（红线，`gate()` 机制保证应用拿不到裸调用点）：危险闸门（应用只能收紧）、
完成裁决调用点、12 停因闭集与 result/trace schema、预算计账、DecisionAsk v6 + prompt 快照、
`needs_value` 值纪律、4 兜底指令。

**反模式**（v4 修订）：①单元内写自由表达式/自拼提示词——单元判定只许产出闭集结果，
动作文本永不从应用产出（三条红线之首）；②安全做成可挂载单元——挂一棵"跳过确认"的树即破防；
③方言自由铸币——算子/停因闭集加载期注册校验。

**树形态解锁**（v3 槽形态给不了的四件）：

| 解锁 | 为什么槽做不到 |
|---|---|
| **`rephrase`（重述题面）成为可放置单元** | 评估文档悬置三轮的"阶梯第 5 档"——固定管线里它没有位置；树里它是 `below-floor` 出边上的一个节点（Roadmap F3a） |
| **弃权路由归应用** | 槽里 abstain 只能硬编码去交接；树里应用声明"先重述、穷尽才交接" |
| **虚拟列表 `expand` 单元**可插在 select-tool 前 | 固定管线插不进新阶段；树加一个节点两条边 |
| **命令行树长出决策冠** | 它不是"第二消费者的槽"，是自己的树：select-tool(候选命令) → resolve-param → invoke(spawn) → verify(exit_code 方言) → check-done |

## 4. 落地（四步）

> **Step A 已实施**（记录见 `CHANGELOG.md`）：`src/engine/decision-tree.ts` 是引擎层的状态契约与
> walker；`src/app/pilot-tree.ts` 是应用层的浏览器树（5 状态 / 16 条边）；`pilot-runtime.ts` 的
> `driveOnce` 只剩引擎强制前置壳 + 一次 `walkTree`，原 `executePicked` 成为四个状态实现。
> 实施中确认的两条：**状态 id 与实现绑定由类型强制**（`Record<BrowserStateId, TreeHandler>`，
> 少实现即编译错），**纠正回环 `verify --retry→ select` 已作为数据存在**（本批未发出该事件）。

**Step A 接缝（可观测面零变化）**：`driveOnce` 的 if 链升格为显式状态机（默认浏览器树）；
引擎 walker（决策面新模块，估 200–300 行）消费；`AppTypeProvider { 方言, 树 }` 在既有组合根
`runExecution` 装配，加载期定死；树放应用层新文件（状态判定薄调冻结实现，估 300–400 行）。

**表化易丢的四个隐性行为**（架构师研判，逐项必须有对应场景钉住）：
① **预算单位**：钉死"一轮树循环 = 一次驾驶步"——若按态计费则一轮拆 5–6 态 ≈ 5× 通胀；
② **跨步账本**：inert 计数、禁选集按 esig 随池换代、rehydrate 重扫仅一次、resume 零模型旁路
——全是数据流不进转移表，须显式入黑板（ctx）并逐项配场景；
③ **守卫次序**：信封守卫先于完成信号——由 walker 前置强制（降为普通态即被应用绕过）；
④ **阶梯池换代**：宽扫 64→128→256 在单次决策内换池——Step A 保留为 select-tool 的
recover 结果**内部行为**（恢复阶梯不拆成显式状态：拆 4 态必重排 prompt 装配序撞逐字节冻结，
且每档多耗一步预算与零变化自相矛盾；CLI 不做 DOM 宽扫暂无第二消费者，出现再迁）。

**场景先行**：golden + 31 场景 + parity 16 钉单步与停因分类**够用；跨步计数器覆盖不足——
搬移前先补 2–4 条跨步场景，否则"平直通过"是必要非充分**。
**回滚纪律**：旧 `driveOnce` 存活一轮真站 smoke 再删，勿被"只减不增"门禁逼早删；
三笔提交中"搬移"笔必须逐字调原函数（早退/fallthrough 不做 1:1 映射就混入重写，红项歧义）。
验证 = `npm run check` 全链 + 补充场景 + `verify:runtime:offline` 8/8 + `verify:run-execution`
golden **平直通过**——可观测面零变化即"树成为代码可指认事实"。

**Step B 修复落树内（引擎文件零 diff）——已实施**：`criteriaView` 空标签身份兜底
（`role` + `[name=…]` + `[type=…]`，只对空标签生效），落在应用层的**提问视图**
（`pilot-tree.ts` 的 `askViewOf`，由 `PilotAskAdapter.host().pick` 注入）。
**引擎文件零 diff 成立**——渲染在注入段完成，`criteriaView` / `ChoiceRequest` 未动；
三条纪律：只补空标签、无可补时返回同一对象（题面逐字节不变）、只改提问视图不动 ref 与执行池。
**这就是三层分界成立的证据**：同一个缺陷，修复落在应用层，引擎只留接口。

**Step C 命令行树**：第二个 `AppTree`——select-tool = 干跑 + 危险确认、invoke = spawn、
verify = exit_code/output_contains 方言；两腿跑同一套契约检查（决策记账 / needs_value /
危险拒绝），命令行腿 0 条 → 同绿。

**Step D 延后**（带归属）：`rephrase` 单元（Roadmap F3a）、`expand` 单元、
context-inject 节点参数 schema、多应用编排（外层循环，复活条件不变）。

## 5. 验收

| # | 指标 | 基线 | 目标 | 测什么 |
|---|---|---|---|---|
| ① | **爆炸半径** | 实测缺陷 `input ""` | 修复只动浏览器树与其 lane：12 停因 / 4 兜底 / CLI 腿零重开；对照"塞引擎"必重开冻结契约——重开数 **0 vs >0** | 归属正确性 |
| ② | **树冠齐平** | 命令行腿 0 条契约检查通过 | 两腿同节点闭集同绿 | 第二棵树真的接上了 |
| ③ | **完成证据率** | — | 两腿 trace"无信号、仅模型票"的完成数 = **0** | 完成裁决权仍在引擎 |
| ④ | **回环边在位** | Maps 实测：fill 成功未提交只能再弃权 | 同场景走 `verify-step.retry → select-tool` 重选 | 纠正回环成为代码事实 |

空标签步基线（实测）：低置信停车/误点 ≈100% → **<20%**；池内有身份时渲染含身份 token ≥95%。
`fill changed=false` 是动作面能力墙，不入本验收（F2b 采集数据点后单独立项）。

## 6. 与冻结 seam 的关系

| Seam | 动不动 | 流程 |
|---|---|---|
| `BrowserMiddleware.run` 唯一执行循环 | **不动** | walker 是决策面循环；invoke 经 gate 走既有执行器 |
| `DecisionAsk` 契约 v6 / `ChoiceRequest` 形状 | **不动** | 引擎接口清单成员 |
| walker 落点 | **新增**（引擎决策面小模块） | 消费应用声明的单元图；`driveOnce` if 链成为默认树数据 |
| `criteriaView` 单源 | **动（归属 + 修复）** | Step A 归属树内 → Step B 修复；单源不变 |
| `AppAdapter` 注册表（声明腿既有 seam） | **对齐对象** | 驾驶腿树与它同一注册纪律 |
| 12 停因 / 4 兜底指令 / 交接 cap 表 / prompt 快照 / split manifest | **按纪律** | 叶子闭集不动；快照与 manifest 按既有纪律重录/删项 |

## 7. 一句话总结

引擎层拥 **状态机执行器与状态契约**（状态闭集、逐类结果闭集、`gate`、终态、预算、
完成裁决调用点）；应用层声明**决策树 = 状态 + 转移表**（状态实现、结果边、纠正回环、
方言注册）——顺序与路由是应用数据；实例层 app.mjs 挂参数。建浏览器树的材料已九成在仓：
**12 停因就是交接终态的原因闭集，4 兜底指令就是托底动作**；真正的新工程只有两件——
把 `driveOnce` 的 if 链升格为显式状态机，并补上"不符合预期 → 回环重选"这条固定管线缺的边。
