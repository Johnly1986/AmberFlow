# 决策模型应用调研与设计改进（2026-10）

目标：参考现有决策模型应用的设计，**只采纳对本项目有实测优势的部分**。每条给出对方做法、
本项目现状、决定与证据；未被采纳的同样记录原因（避免下次重复调研）。

## 逐条判断

| 参照的做法 | 本项目现状 | 决定 | 证据 |
|---|---|---|---|
| **观测瓶颈**：模型只能从被展示的元素里选 | 元素池上限 40；只有"计划点名了 hint"才会 JS 回捞（`hintLookup`） | **采纳**——低置信时加一次"加宽观察"（40 → 120 元素）再决策 | 机制 A/B：70 个诱饵按钮把真目标挤出预算 → 关掉重观察**阻塞**（`low confidence 0.0x < floor 0.25`）、打开则**恢复**且轨迹记录 `laya:reobserve`（`tests/reobserve.test.ts`） |
| **决策缓存**：重放已决策行为 | laya 是确定性的，但每次 pick 都真实前向；重试/重规划/续跑/消融会重复问同一问题 | **采纳**——`withDecisionCache`（精确键 = 状态指纹 + 问题指纹，可整体关闭）＋ JSONL 决策日志 | 真模型、同一份计划跑两遍：无缓存 **12 次前向**（每遍 6 次），有缓存**共 6 次**——**第二遍 0 次前向、9.2s → 1.3s**（`tools/cache_measure.ts`）。键包含完整状态与问题，页面一变即 miss，不存在"陈旧命中" |
| **弃权信号之一：top-two 间隔** | 只有置信度地板（0.25） | **实测后不采纳**（保留为诊断） | 见下"实测否决"第 2 条：任何能拦住坏动作的阈值都会杀掉远多的好动作 |
| **快路径 + 深思路径分层** | 规则 → laya → 重观察 → **升级（新）** → 停止 / 人工确认 | **采纳**：补上 pick 级升级 `escalateFn` / `llmEscalator` | 见下"采纳 ③"：升级者是**选择器**不是规划器，只能从已展示候选里点名；发明候选被拒；失败即弃权 |
| **让模型自选观测 / 写代码（raw CDP）** | 冻结计划 + 规则优先 + 完成只认 DOM 信号 | **不采纳** | 与本项目的三条硬约束冲突（不重规划、不发明取值、完成只认 DOM 信号）。对方的前提是"模型足够强到可以自由行动"，本项目的目标是"模型不可信时流程仍然可控"；观测瓶颈这一**问题**被采纳，其**解法**（放弃受控观测）不被采纳 |
| **多策略定位回退（自愈）** | hint 已分级（精确属性 → 末段路径 → 全子串）、计划点名优先、元素签名禁选、重观察 | **已有**，无需改动 | 线上包 8/8、11/11 子目标全部 `rule:match`（零模型选择） |
| **模型作者自带的注入问句**（`guard_questions().prompt_injection`） | 手写的攻击问句，阈值 0.95（`path-a.ts`） | **不采纳** | 三页实测（真模型，`src/tune-guard.ts`）：preset 措辞在正常页给 **0.969 / 0.930**，**超过 0.95 阈值** → 会把正常页误判为注入；我们的 A 措辞是 **0.907 / 0.940**，恰在阈值下，攻击页三者都是 1.000。preset 是为"用户提示词"调的，不是为"页面文本" |

## 本轮落地（都有测试与数字）

1. **低置信重观察** `src/executor.ts`（`RunOptions.reobserve`，默认开）
   - 只在"即将停止"的失败路径付费：一次加宽抽取（`WIDER_ELEMENTS=120`）+ 重新决策；命中则轨迹记 `laya:reobserve`，审计可见。
   - 抽取层的预算变成参数（`extractElements(page, jsProbe, maxElements)`），默认不变。
2. **决策缓存 + 决策日志** `src/decision-cache.ts`
   - 精确键（状态 + 问题指纹，`sha1`）、插入序淘汰、`decisionStats()`、`resetDecisionCache()`；日志每行一条决策（含 `cached` 标记），是"可重放轨迹"的一半。
   - 实测：无缓存 12 次前向 / 第二遍 9.2s；有缓存共 6 次前向 / 第二遍 **0 次前向、1.3s**；缓存外侧/内侧计数差异也暴露过一个测量陷阱（命中不能算前向），已修。
3. **top-two 间隔诊断**：轨迹的每一步在 `method` 为 `laya*` 时附带 `margin`（数值），为下一轮的弃权门提供数据。
4. **顺手修掉一个引擎边界缺陷**：决策分布为空时 `Math.max()` 返回 `-Infinity`，停止原因会打印 `low confidence -Infinity`；现在回落到答案自带的置信度。

## 采纳 ③：pick 级"深思路径"（`escalateFn` / `llmEscalator`）

C3-R 的第二级是独立于快路径的深思维径。本项目补上这一级，但按自己的契约收窄：
**升级者是"选择器"，不是"规划器"**——它只拿到本地模型看到的那份候选视图，只能点名其中一个 ref；
答不出（`null`）、答非候选视图里的 ref、或端点报错，一律**弃权**（fail closed），流程回到原来的阻塞行为。

- 触发点：本地模型低于地板、且一次加宽观察也没救回来之后（失败路径才付费；每步最多一次）。
- 升级者看到的是**加宽后的视图**（>40 候选）。实现时这里踩过一个真 Bug：只有当本地模型恢复成功时才替换池子，
  于是升级者拿到的是窄池、目标仍不可见——已修（加宽一旦发生即成为该步视图）。
- 轨迹记录 `method: "escalate"` + `escalated: true`，审计可分辨"这一步是更强的推理者挑的"。
- 离线测试（`tests/escalate.test.ts`）：升级恢复原本阻塞的子目标；发明候选被拒；本地模型自信时不会被覆盖；抛错也不崩。

## 实测否决 ②：top-two 间隔（C3-R 的弃权信号）不适合本项目

样本：线上 8 站、**关掉规则层**（`--force-rules off`，纯模型选择）共 70 个模型步——39 个好动作、
5 个坏动作（执行了但惰性）、26 个未执行（置信度不足弃权/受阻）。

| 阈值（margin < t 判弃权） | 拦住坏动作 | 误杀好动作 |
|---|---|---|
| 0.02 | 0/5 | 0/39 |
| 0.05 | 1/5 | 1/39 |
| 0.10 | 1/5 | **7/39** |
| 0.15 | 1/5 | **17/39** |
| 0.20 | 2/5 | 18/39 |
| 0.30 | 2/5 | 27/39 |
| 0.50 | 4/5 | 31/39 |

坏动作的 margin 中位数 **0.348**，反而**高于**好动作的 0.263；最坏的几例里有一个 margin **0.942**
（模型极度自信，仍然点了一个惰性元素）。也就是说：本系统的"做错"不是"在两个选项间犹豫"，
而是"自信地点了看似合理但无效的东西"——置信度地板 + 惰性检测 + 重观察已经在处理这一类，
margin 门看不出它。**结论：不采纳为门，只保留诊断字段**（`trace.margin`）。

顺带量化了规则层的价值（同一批线上用例）：**规则开 8/8 vs 规则关 4/8**。

## 实测否决 ③：切片级"校准门"（C3-R 的"校准不足不决策"）

C3-R 要求"held-out、切片级的校准之后才做决策"。项目其实早就把作者的 ECE 指标移植进来了
（`eceScore`），但一直没用在**决策**上。本轮补上仪器并做了两次测量（`npm run calibration`，
数据 = 离线夹具矩阵 + 线上 8 站，两批都 `--force-rules off`，即纯模型选择）。

仪器把每条轨迹变成两个标签的可靠性表：
- **动作级**：执行了且页面有变化 = 有效；
- **任务级**：该步所属子目标最终 `done`。

80 个模型步（53 个有结果，27 个无结果被排除）：

| 切片 | n | 平均自信 | 动作级准确率 / ECE | 任务级完成率 / ECE |
|---|---|---|---|---|
| english | 51 | 0.498 | 0.922 / **0.441** | 0.314 / **0.200** |

分桶更刺眼（动作级）：

| 自信区间 | n | 平均自信 | 有效比例 |
|---|---|---|---|
| 0.2–0.4 | 20 | 0.301 | **0.950** |
| 0.4–0.6 | 21 | 0.492 | 0.905 |
| 0.8–1.0 | 9 | 0.939 | 0.889 |

**自信度是倒挂的**：最低自信段反而最"有效"。任务级也严重高估（平均自信 0.498，实际完成 31.4%）。

于是做了一次直接 A/B——**把置信度地板从 0.25 降到 0.10**（同一批线上用例、同样关规则）：

| 配置 | 用例 | 子目标 |
|---|---|---|
| 地板 0.25（默认） | 4/8 | 6/11 |
| 地板 0.10 | **4/8** | **6/11** |

**什么都没改变**。两个结论合起来很清楚：

1. 在这些真实页面上，原始置信度既不能预测"动作是否有效"，也不能预测"子目标是否完成"（ECE 0.20–0.44）；
2. 因此**基于置信度的门（无论地板还是"校准门"）都不是这里的关键**：把地板降 2.5 倍不改变任何结果，
   而**规则层**一开就是从 4/8 变成 8/8。真正的杠杆是"让模型少被问到"（规则/hint/计划点名），不是"问得更准"。

**决定：不在运行时里加切片校准门**，把仪器留下（`npm run calibration`），数据攒够或换到别的切片再重测。
另外注意：本项目在**唯一一个校准确实极差的切片**上早就是这么做的——英文 checkpoint 在 CJK 上 ECE 0.855，
于是路由按**脚本**而不是按自信度（`laya.Router` + `camera_entry` 的"类型列优先"规则）。
也就是说 C3-R 这条要求的**精神已经在项目里以"不信任自信度、改用确定性信号"的形式落地**，
本轮测量只是说明：在这些页面上再加一道通用校准门，收益为零。

## 采纳 ④：结果记忆（缓存"结果"，而不只是"决策"）

第 2/3 轮测出：真实页面上的坏动作不是"低置信的犹豫"，而是**自信地点击看似合理但无变化的元素**
（最坏一例自信度 0.890）。置信度类的门看不见这种错误，但**结果本身**看得见。于是把决策记忆补成两半：

- `withDecisionCache` 记"模型决定了什么"（同状态同问题不再重复前向）；
- `OutcomeMemory` 记"实际发生了什么"：某个元素在这张页面 + 这个子目标上被证明**惰性**，
  那么重试 / 续跑 / 重跑时不再走进它。

范围与安全性（避免变成陈旧黑名单）：

| 规则 | 做法 |
|---|---|
| 键 | **精确 url + 子目标**（页面不同、目标不同 = 不同的记忆） |
| 身份 | 元素**签名**（tag\|label\|href\|data-test）——ref 每次扫描都重排，绝不能持久化 |
| 失效 | 该元素一旦**有效**立即清除标记（页面会变） |
| 边界 | 有上限（键 256 / 每键 32，LRU）；**绝不因此清空候选池**（必须还剩至少一个别的候选才跳过） |
| 可见 | 轨迹记录 `prevented: n`；`stats()` 给出 prevented / cleared |
| 持久化 | 可选 JSON（续跑跨进程生效）；文件损坏就当没有记忆，绝不因此让流程失败 |

机制证据（`tests/outcome-memory.test.ts`，9 条）：两个按钮、第一个点击无变化且**措辞刻意让规则命不中**
（否则规则会替模型决定，测试会因为错误的原因通过）——第 1 次点中死元素、预算耗尽；第 2 次记忆把它移出候选，
选中真按钮并完成，轨迹记 `prevented: 1`。**对照组**（无记忆）两次都以同样方式失败。
另有单元测试覆盖键的作用域、有效即清除、双向上限 + LRU、跨进程持久化、坏文件降级，
以及"记忆中的元素是唯一候选时仍然可点"。

**真模型实测（线上 8 站、关规则、A/B）**

| 配置 | 用例 | 子目标 | 记忆是否生效 |
|---|---|---|---|
| `--outcome-memory off` | 4/8 | 6/11 | — |
| `--outcome-memory on` | **4/8** | **6/11** | 生效：学出 4 个 (url×子目标) 键 / 8 条惰性签名；85 步中 **8 步**因记忆剔除了候选，共 **39 次**候选被跳过 |

**决定：作为可选能力（默认关）**，而不是默认门。原因就是上表：机制确实在真实页面上生效，
但**结果指标没有变化**——这批被阻塞的子目标不是"撞死在同一个死元素上"，
而是"关闭规则后模型压根找不到正确元素"。记忆解决的是前者。
因此：保留为 opt-in（`--outcome-memory on` + `runCase(..., mem)` / `BrowserMiddleware({outcomeMemory})`），
把"能省掉重复无效动作"的机制证据和"不改变成败"的结果证据一起记在这里，
等出现**重试密集、且失败原因是重复死动作**的切片再默认打开。

**过程中的一个真事故（已钉成回归测试）**：第一次 A/B 里 `BenchMiddleware` 收下了 `outcomeMemory` 选项却
**没有转发给 `super()`**，于是执行器一直是 null——跑分照常"看起来正常"，两次结果一模一样，
差一点就被当成"记忆无收益"的结论。现在 `tests/outcome-memory.test.ts` 里有一条
"harness 必须保留它收到的记忆"的断言：**静默丢选项比崩溃更危险**。

## 采纳 ⑤：学习型 hint（把"观察到的成功"变成规则）

前几轮反复测到同一个杠杆：真实页面上**让模型少被问到**比让模型答得准重要得多
（同一批线上用例：有手写 hint 8/8，没有则 4/8）。但 hint 一直是**手写产物**（规划器看 DOM 快照写、`plan_cli --hint` 手写）。
这一轮让它可以被**挣得**：

- 某次**模型选择**（或升级）真正推进了子目标 → 该元素的**稳定 handle** 变成一条 hint
  （`data-test` → `id` → `name` → `tag[near~label]`，值必须是稳定的：4+ 位数字、哈希、计数一律拒绝）；
- 键同样是**精确 url + 子目标**；只在该步**计划没有 hint** 时才生效（手写 hint 永远优先）；
- 语法完全复用现有 hint 语法 ⇒ 学到的 hint 若匹配不到或有歧义，仍然回落到模型——**错误的 hint 不会变成陷阱**；
- 可限界、可落盘（第二遍/续跑直接 `rule:match`，零模型调用）。

认识论上与"完成信号要观察不要猜"一致：hint 是**看来的**，不是预测来的。

机制证据（`tests/hint-memory.test.ts`，9 条）：第 1 遍模型选中目标、归纳出 hint、子目标完成；
**第 2 遍由 hint 直接解出（`rule:match`），模型调用次数为 0**；无记忆的对照组第 2 遍仍然问模型；
手写 hint 优先于学习到的；写坏的 hint（匹配不到）不会让流程卡住。

**真模型实测（线上 8 站、`--force-hints off`：剥掉手写 hint，规则仍开）**

| 配置 | 用例 | 子目标 | 模型选择步 | 规则命中步 |
|---|---|---|---|---|
| 基线（无 hint、无记忆） | 3/8 | 4/11 | 105 | 49 |
| 第 1 遍（学习，同一记忆文件） | 3/8 | 4/11 | 96 | 44 |
| 第 2 遍（复用学到的 hint） | 3/8 | **5/11** | **91** | 37 |

这一轮同时得到一个**干净的 hint 价值量化**：同一批线上用例，**有手写 hint 8/8，剥掉后 3/8**。

学到的东西质量不错——学习遍只成功了 2 个子目标（只有"成功"才配归纳出 hint），得到 2 条：

```
https://shop.polymer-project.org/#... -> a[near~Men's Outerwear Shop Now]
https://zh.wikipedia.org/w/index.php?search=图灵&... -> a[near~艾伦·图灵]
```

第二条正是当年**手写** hint 针对的那个规范链接（第 1 轮为它解决过 17 个链接的歧义问题）——
模型自己成功找到过一次，流程就把这条经验固化成了规则。

**但必须说清楚归因的边界**：线上站点逐次波动很大（三腿总步数 154/140/128，Wikipedia 还会返回错误壳），
所以"第 2 遍多出 1 个子目标"**不能算作因果**。可以确定的只有：
(1) 机制本身在 A/B 测试里被钉死（复用遍零模型调用）；
(2) 复用遍的模型选择步数低于学习遍（96 → 91），被学到的 zh.wikipedia hint 命中的那个子目标
从 4 步降到 1 步；
(3) 学到的 hint 只能摊薄**曾经成功过**的子目标，救不回模型从没解决过的子目标——这正是用例数没变的原因。

**决定：保持 opt-in**（`--hint-memory on` / `BrowserMiddleware({hintMemory})`）。
要证明它值得默认开启，需要一个**重复执行同一份计划**的无噪声协议（像 `cache:measure` 那样在同一进程里跑两遍），
而不是依赖线上两腿的对比；这是下一轮的第一件事。
