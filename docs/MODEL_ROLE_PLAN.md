# 分工修正方案：让决策模型出现在它能赢的地方

> 出处：[docs/DECISION_MODEL_PURPOSE_REVIEW.md](DECISION_MODEL_PURPOSE_REVIEW.md)（独立审查）的结论——
> **"配置承重、模型兜底"这个现状没有错，错的是把模型放在运行期做它最不擅长的那件事，而它擅长的事没人用。**
> 本文只回答一个问题：**怎么改，以及改完拿什么数验收。**
>
> 每条都带：改什么 → 为什么它能修"反向" → **验收判据（可测的数字）** → 代价/风险 → 诚实边界。
> 本文**不含实现**：落地与否、先做哪条，由项目方裁定（§5 列了需要裁定的三件事）。
> **执行层面（阶段划分 / 任务卡 / 门禁 / 停止条件）见 [docs/MODEL_ROLE_IMPL_PLAN.md](MODEL_ROLE_IMPL_PLAN.md)。**

## 0. 现状的三个数（全部来自本机实测，复算入口见审查文档 §1）

| 数 | 值 | 含义 |
|---|---|---|
| 浏览器步里手写了目标的比例 | **169/171 = 98.8%** | 选目标这件事，配置已经做完了 |
| 真模型下整批已验收语料的选择提问 / 过关 | **5 次 / 0 次**（201 步，`rule:match` 201/201） | 模型在正确性上没有贡献 |
| 闸门内的 precision | **passthrough 3/57 = 5.3%（AUC 0.233，反向）**；shortlist 8/18 = 44.4%（AUC 0.587） | 不是"模型不行"，是**两把尺子混用 + 问法太大** |

以及两条"改得动"的线索：

- **窄问**：在当初逼出 P1 的两个维基结果页上，档内 2 条候选时模型 **14/14 选对**（margin 0.10–0.23），
  但 `confidence` 只有 0.003–0.037，**全被 0.25 闸门拒绝**；同一页的全池提问只对 3/14。
- **页面裁决**：`camera-entry` 的 4 步模型 **4/4 选对**（conf 只要 0.01）——那 4 步的答案会被表单自己校验，
  错了也进不去。**错误动作便宜的地方，模型是可用的；不可逆的地方它不可用。**

## 1. A 组｜运行期：把"问法"和"闸门"修对（最小改动、最大杠杆）

### A1（P0）闸门换成"按问法归一"的信号，并且**两把尺子分开用**

- **改什么**：`pickElement` 现在无论问法大小都拿 `conf` 与同一个 `floor` 比。改成：
  `RunOptions.gate = "confidence" | "margin" | "top1"`（**默认仍是 `confidence`，逐字节等价**），
  窄问/短名单这类"小问题"用 `margin = p(top1) − p(top2)` 或 `p(top1)`；
  同时把 `by_question_shape` 的两支拆开各自标定（本语料：passthrough 137 步 / shortlist 25 步）。
- **为什么修反向**：模型的**选择**在窄问上是对的（14/14），是**尺度随选项数变化**的置信度把它判死；
  反过来，40 选项里的错误答案更容易拿到高 conf（0.226–0.467）。换一个不随选项数变形的信号，
  闸门才可能在"对的"那一侧开、在"错的"那一侧关。
- **验收判据**（全部离线可复算）：
  1. `npm run model:contribution` 的 `by_question_shape` 两栏，在新口径下 **AUC ≥ 0.5 且 floor 0.25 处 precision 高于现状**（现状 0.233 / 0.587）；
  2. 两个维基页（`tools/ask-shapes.ts`）+ 一个**hold-out 页面**上，窄问的正确答案能过闸门；
  3. **默认档不动**：六层对拍与 `apps:suite` 逐字节不变（`gate: "confidence"` 是缺省）。
- **代价**：改动集中在 `pickElement` 一处 + 一个标定脚本；风险 = 闸门变松会把错误动作放进去
  → **必须与 A2 同批上**（放开的只有"页面能拒绝"的步）。
- **边界**：标定数据是**本机 162 步 + 2 张真机页**，不是普适结论；换机器/换 checkpoint 要重标。

### A2（一）"模型提议、页面裁决"：只在**错误动作便宜**的步上放开模型

- **改什么**：给步的声明面加一个开关（名字待定，比如 `propose: "adjudicated"`），
  只允许在**非破坏性、且有可判定信号**的步让模型选元素；链接跳转、不可逆动作继续"规则优先、模型不参与"。
  加载期规则：不可逆步写了这个开关 ⇒ **红**。
- `[复核修正]` 措辞要更准：这类步的**安全性**来自"动作本身非破坏性 + 该步有 DOM 信号兜底"，
  **不是**"页面会拒绝错误动作"——下拉选错值页面是照收的，只是信号不成立、这一步白跑。
  语料里的分布（按实测 `expected` 元素的真实标签分类，162 个可判步）：
  **`select` 65（40.1%）+ `input` 16（9.9%）= 50.0% 非破坏性**，`button` 50（30.9%）+ `a` 31（19.1%）= 50% 点击类；
  其中真正会被页面**校验**拒掉的只有 `input` 那一档（**9.9%**）。
  ⇒ A2 的覆盖面是 **~50%**（"错了白跑，但不会点错东西"），不是 100%；验收里那条"错误动作被采纳 = 0"
  必须按"非破坏性"定义，不能按"页面拒绝了它"定义。
- **为什么修反向**：错答解剖显示 **89/122 个错答选了导航/品牌元素**——模型被"页面显眼程度"带偏；
  而页面裁决是一道免费的第二闸门：错了就填不进去/提交被拒，**不会变成"点了购买"**。
- **验收判据**：
  1. `camera-entry` 删掉全部 hint 后，从 **0/4 → 能走完**（页面自己拒绝错误动作）；
  2. 报告里"错误动作被采纳"计数为 **0**，且新增"页面拒绝次数"作为安全指标；
  3. 不可逆步上使用该开关 ⇒ 加载期报错（负例进测试）。
- **代价**：schema + 执行器的小改；风险 = 误标导致错误动作被执行 → 所以开关只对"页面能拒绝"的面开放。
- **边界**：`camera-entry` 是 4 步的小样本；要再找 2–3 个大表单类页面复现。

### A3（独立、纯赚）把"兜底"的运行成本挪走：风险头/noul 的调用策略

- **改什么**：① 风险判定改成**规则优先**（`DESTRUCTIVE_PATTERNS` 命中即定），模型只对
  "规则未命中 **且** 动作不可逆"的步投票；② 让 `withDecisionCache` 覆盖风险头
  （同一 `(state, desc)` 不重复问；今天缓存只作用于 `predictShortlist`）。
- **为什么**：真模型在位把同一批语料从 **160.7 s**（脚本桩实测）拉到 **597 s**，而**选择提问只有 5 次**——
  这段开销几乎全是每步一次的风险头。它买到的东西只是"要不要问人一次 y/n"。
- **验收判据**：语料墙上时间回到 **< 300 s**；危险步的拦截行为不变
  （`cli-report`/`--confirm-safe` 那批负例仍绿，危险步拒绝率不变）。
- **代价**：一处 gate + 一行缓存键；**风险最低的一条**，可以立刻做。
- **边界**：省的是时间，不是能力；如果将来要给风险头换成更强的分类器，这条要重看。

## 2. B 组｜作者期：让模型做它真正擅长的事（最高杠杆，但本机缺端点）

### B1（二）"提议档"：模型提议 (hint, signal) 候选，人只做确认

- **改什么**：`plan:flow` / `learn` 现在是**纯观察 + 归纳**（`tools/learn.ts`、`plan-flow.ts` 全流程零模型）；
  加一个**提议档**：模型看元素池 + 这一步的意图，给出 K 个候选 (hint, signal)；
  **裁决仍走既有的确定性三关**（判别性 / 稳定句柄 / 跨演示可复现），人只回答"是不是这个"。
  模型排序、归纳裁决 —— 与 `apps:induce` 的现有纪律不冲突。
- **为什么修反向**：作者期错了有人兜，运行期错了没人兜；而声明里的大部分是机械展开、
  真正的人写判断只有几十条 —— 瓶颈在**判断**，不在**选择**。模型在"理解意图"这一侧的产出
  可以直接减人写行数，而不是在运行期抢一个 25% 的选择题。
- **前提要按今天的数复核（独立复核指出，已改）**：初稿引用的「61% 机械行 / ~31 条判断」是
  **15 个包、2965 行时代**的数（`bench/AUTHORING_ASSESSMENT.md`）；今天（19 个有 journey 的包、
  pack 3238 行）同口径是 **journey+roles 57.1%（1848/3238）**，人写判断 **37 条**。
  更要紧的是：**那 57% 已经由零模型的 `apps:gen` 吃掉**（8/8 对拍、生成包 2076 行 = pack 行的 64.1%），
  真正还能被"提议"压缩的手写面只剩 **≈493 行（约 13%）**。
  所以 B1 的收益上限是 **13% 的手写行**，不是 61% —— 立项前请按这个数量级重新评估性价比。
- **验收判据**：同一批已录/已生成的应用做回放实验 ——
  ① 人写行数下降的百分比；② 提议→被接受的比例（入报告）；③ **零模型重放门仍全绿**（learn 的既有落盘门槛）。
- **代价**：需要一个 LLM 端点；**本机没有**（`LLMPlanner` 从未实跑，只有离线单测）。
  ⇒ 现在只能先落**机制与判据**（用 scripted 替身跑通管线），质量数字等端点到位再测。
- **边界**：不碰 `invariants`（"什么必须成立"必须是人写的判断）；也不让模型写 `dangerous`。

### B2（前置）把 LLM 端点这一格补上，否则 B1 永远只是设计

- 命令已经存在（`OPENAI_BASE_URL` + `OPENAI_API_KEY` → `LLMPlanner`/`LLMAuditor` 自动启用），
  审计器也还停在 `MockAuditor`。**这一步没有代码工作量，只有环境配置**；
  但它决定了 B1 能不能验收。若长期不接端点，B1 应明确记为"未实现"，而不是"接近完成"。

## 3. C 组｜验收与制度：让"反向"不会再悄悄发生

### C1（零风险）把两个数变成一等公民

- `apps:suite` / `apps:matrix` 各加一列：**hint 覆盖率**（今天没有这一列）与
  **闸门内 precision**（来自 `npm run model:contribution` 的摘要）。
- 判据：报告里能一眼看到"这一轮有多少步是靠声明解决的、有多少步真的需要模型、模型被采纳时对了几成"。
  覆盖率 < 100% 时**明着标注**"其余步依赖模型兜底"。

### C2（零风险）"漂移夹具"：给弹性一个会红的验收台

- 现状：删掉全部 hint 的 A/B 证明"没有声明就红"（4/4 → 0/4），但**没有"页面变了"的固定夹具**。
- 改：加一对夹具页（同一页面：原样 / 改掉 id 与层级），断言
  ① 现状下"改过的"那份**红**（这是今天的真实行为，先把账记上）；
  ② A1/A2 落地后，同一份夹具要**能靠窄问 + 页面裁决走完**——这才是"弹性"有牙的定义。
- 判据：夹具进 CI；红/绿可复现；不允许用"跳过"当通过。

### C3（零风险）把分工写进文档

- README/ARCHITECTURE 明说：**声明是主路径、模型是兜底 + 诊断 + 作者期助手**，
  并附本轮的两个数（hint 覆盖率、闸门内 precision）。

## 4. 如果一条都不做：另一条同样诚实的路

把模型**明确降级**为"风险头 + 诊断"：`escalate`（LLM 老师）在语料里出场 0 次、`reobserve` 挽回 0 步，
两者都是死重；这样可以直接省掉 ~600 s→240 s 的语料时间、以及 1.7 GB 的产物依赖。
代价是放弃"页面变了还能自己找路"的弹性主张——**但那个主张今天本来也没有被任何数字支持**
（删声明即 0/4）。这条路不需要新代码，只需要改文档与删除 `escalate` 的接线。

## 5. 建议的落地顺序

| 顺序 | 条目 | 理由 | 前置 |
|---|---|---|---|
| 1 | **A3**（风险头策略 + 缓存） | 纯赚、独立、可立刻量（597 s → <300 s） | 无 |
| 2 | **C1 + C2 + C3** | 零风险，先把"记账"和"会红的验收台"立起来，后面每条都有落点 | 无 |
| 3 | **A1 + A2 同批** | 修"反向"的核心；两者互为补偿（放开模型 ⇄ 页面裁决） | C2 的夹具作为验收台 |
| 4 | **B2 → B1** | 最高杠杆，但被端点卡住；端点到位后先量"提议接受率"再谈质量 | LLM 端点 |
| — | （备选）§4 降级路线 | 只有在项目方放弃"运行期弹性"主张时才选 | 需要裁定 |

## 6. 需要裁定的三件事

1. **接受"配置承重、模型兜底 + 作者期助手"的定位**并写进 README/ARCHITECTURE 吗？（C3）
2. **A1 + A2 立项吗？** 它要动闸门语义（新增档位、默认不变），是本方案里唯一有行为风险的一条。
3. **LLM 端点接不接？** 不接的话 B1/B2 应当明确记为"未实现"，而不是继续挂在路线图上。

> 复算入口：`npm run model:contribution -- --out /tmp/mc.json`（摘要现在**分开报**两把尺子：
> `by_question_shape.passthrough_pool_le_8` / `.shortlist_pool_gt_8`，含各自 AUC 与 floor 0.25 的 precision）；
> 真机换问法：`tools/ask-shapes.ts`（用法见审查文档 §1）。
